# Data Model: Диагностика и безопасная остановка сессии печати

**Feature**: `001-print-session-diagnostics` | **Date**: 2026-11-02

Все структуры — с `#pragma pack(push,1)`, без динамической памяти, размеры —
именованные константы (`FB_G6_PRINT_JOURNAL_*`). Байтовые раскладки с точными
смещениями — в [contracts/journal-storage.md](./contracts/journal-storage.md).
Коды причин и источников — в [contracts/stop-reasons.md](./contracts/stop-reasons.md).

---

## 1. Перечисления

### `StopCause` (`uint8_t`)

| Код | Имя | Смысл | Требование |
| --- | --- | --- | --- |
| `0x00` | `CAUSE_COMPLETED` | штатное завершение файла | FR-005 |
| `0x10` | `CAUSE_ABORT_LOCAL_UI` | отмена пользователем с экрана/меню | FR-005 |
| `0x11` | `CAUSE_ABORT_NETWORK` | отмена командой по WiFi (M26) | FR-004, US3 |
| `0x12` | `CAUSE_ABORT_HOST` | отмена из консоли/хоста (M524) | FR-004 |
| `0x20` | `CAUSE_MEDIA_ERROR` | извлечение/сбой SD-карты | FR-004, US1/5 |
| `0x30` | `CAUSE_RESET_WATCHDOG` | сброс сторожевым таймером | FR-001 |
| `0x31` | `CAUSE_RESET_POWER` | сброс по питанию (включение/просадка) | FR-001 |
| `0x32` | `CAUSE_RESET_SOFTWARE` | программный/кнопочный сброс | FR-001 |
| `0x40` | `CAUSE_EMERGENCY_THERMAL` | авария термозащиты | FR-005, FR-013 |
| `0x41` | `CAUSE_EMERGENCY_M112` | авария по M112 | FR-005 |
| `0x48` | `CAUSE_EMERGENCY_OTHER` | прочий `kill()` (homing, probe, fan, TMC…) | FR-005, FR-007 |
| `0x50` | `CAUSE_INTERNAL_STOP` | `stop()` без `kill()` (ошибка probe и т.п.) | FR-007 |
| `0x7F` | `CAUSE_UNKNOWN` | причина неизвестна | FR-007 |

Правила: значения неизменны (FR-010); новые причины добавляются внутри своей
группы (`0x1x`, `0x2x`, …); неизвестный код при чтении отображается как
`MSG_STOP_CAUSE_UNKNOWN` без потери записи.

### `StopSource` (`uint8_t`)

| Код | Имя | Кто инициировал |
| --- | --- | --- |
| `0x00` | `SOURCE_UNKNOWN` | не определён |
| `0x01` | `SOURCE_LOCAL_UI` | TFT-экран или меню принтера |
| `0x02` | `SOURCE_NETWORK` | MKS WiFi |
| `0x03` | `SOURCE_HOST` | консоль/USB-хост (M524, emergency-парсер) |
| `0x04` | `SOURCE_MEDIA` | сбой/извлечение носителя |
| `0x05` | `SOURCE_FIRMWARE` | внутренняя логика (завершение, защита, сброс) |

### `SessionStage` (`uint8_t`)

| Код | Имя | Когда пишется |
| --- | --- | --- |
| `0x00` | `STAGE_NONE` | сессия не активна |
| `0x01` | `STAGE_PRINTING` | старт и продолжение печати |
| `0x02` | `STAGE_PAUSED` | пауза (`did_pause_print`) |
| `0x03` | `STAGE_FILAMENT_CHANGE` | пауза на смену филамента (`PAUSE_MODE_CHANGE_FILAMENT`) |
| `0x04` | `STAGE_FINISHING` | файл дочитан, ожидается `M1001` |

### `StopFlags` (битовое поле в `uint8_t`)

| Бит | Имя | Смысл |
| --- | --- | --- |
| 0 | `FLAG_EMERGENCY` | остановка через `kill()` |
| 1 | `FLAG_ESTIMATED_DURATION` | длительность взята из контрольной записи (сброс) |
| 2 | `FLAG_UNRECORDED_EMERGENCY` | авария была, но запись в журнал не удалась |
| 3 | `FLAG_EMERGENCY_DETAIL_LOST` | деталь аварии утеряна (`noinit` не пережил снятие питания) |

## 2. Сущности

### 2.1 `StopEvent` — событие останова (28 байт)

| Поле | Тип | Правило |
| --- | --- | --- |
| `seq` | `uint32_t` | монотонный номер, `0` = пустой слот; источник порядка «новые сверху» |
| `duration_s` | `uint32_t` | секунды от старта задания (`print_job_timer.duration()`); при сбросе — контрольное значение с `FLAG_ESTIMATED_DURATION`; ограничение `0..999999` |
| `percent` | `uint8_t` | `card.percentDone()`; `0xFF` = неизвестно |
| `cause` | `uint8_t` | `StopCause` |
| `source` | `uint8_t` | `StopSource` |
| `stage` | `uint8_t` | `SessionStage` на момент останова |
| `flags` | `uint8_t` | `StopFlags` |
| `crc8` | `uint8_t` | CRC8 по байтам `0..12` и `14..27` |
| `file` | `char[13]` | имя файла DOS 8.3 (`card.filename`), NUL-дополненное |

Инварианты:
- `seq` строго возрастает; при переполнении `uint32_t` (≈4 млрд событий)
  допускается сброс счётчика, порядок тогда определяется положением в кольце;
- имя файла всегда NUL-терминировано внутри 13 байт (при чтении
  принудительно `file[12] = '\0'`);
- `duration_s` не уменьшается в пределах одной сессии;
- событие с неверным `crc8` не отображается и не блокирует чтение остальных.

### 2.2 `JournalHeader` — заголовок журнала (12 байт)

| Поле | Тип | Правило |
| --- | --- | --- |
| `magic` | `uint32_t` | `0x314A4246` (`"FBJ1"` little-endian) |
| `version` | `uint8_t` | `1`; несовпадение → журнал считается пустым без ошибки |
| `slots` | `uint8_t` | `FB_G6_PRINT_JOURNAL_SLOTS`; несовпадение → журнал пуст |
| `head` | `uint16_t` | индекс следующей записи, `0..slots-1` |
| `count` | `uint16_t` | заполнено, `0..slots` |
| `crc16` | `uint16_t` | Marlin `crc16()` по байтам `0..9` |

Правила восстановления:
- если `crc16`/`magic`/`slots` неверны → пересобрать заголовок сканированием
  слотов: `count` = число валидных, `head` = (индекс слота с максимальным
  `seq` + 1) mod slots;
- если валидных слотов нет → `count = 0`, `head = 0` (журнал пуст, не ошибка).

### 2.3 `ActiveSession` — активная сессия (32 байта, 2 слота)

| Поле | Тип | Правило |
| --- | --- | --- |
| `magic` | `uint32_t` | `0x31415346` (`"FSA1"`) |
| `seq` | `uint32_t` | номер записи слота; выбирается слот с большим `seq` |
| `elapsed_s` | `uint32_t` | контрольная длительность |
| `percent` | `uint8_t` | контрольный процент, `0xFF` = неизвестно |
| `stage` | `uint8_t` | `SessionStage` |
| `active` | `uint8_t` | `1` — сессия идёт, `0` — корректно закрыта |
| `crc8` | `uint8_t` | CRC8 по остальным байтам |
| `file` | `char[13]` | имя файла DOS 8.3 |
| `reserved` | `uint8_t[3]` | нули |

Правила:
- слоты чередуются (`seq & 1`), поэтому сбой записи портит максимум одну копию;
- при загрузке берётся валидный слот с большим `seq`;
- `active = 1` на загрузке ⇒ предыдущая сессия прервана ⇒ синтезируется
  `StopEvent` с `CAUSE_RESET_*` и `FLAG_ESTIMATED_DURATION`, после чего слот
  закрывается (`active = 0`, `seq++`); если последнее событие журнала уже
  терминальное (`COMPLETED`, `ABORT_*`, `MEDIA_ERROR`, `INTERNAL_STOP`,
  `EMERGENCY_*`) и его `duration_s` не меньше `elapsed_s`, синтез не выполняется
  (защита от дубля после штатного завершения);
- `active = 0` на загрузке ⇒ события не создаются (штатное завершение или
  отсутствие печати), что исключает задвоение (edge case спеки).

### 2.4 `StopJournal` — агрегат (RAM + EEPROM)

| Поле | Тип | RAM | EEPROM |
| --- | --- | --- | --- |
| `header` | `JournalHeader` | 12 Б | 12 Б |
| `slots[]` | `StopEvent[16]` | 448 Б | 448 Б |
| `active[2]` | `ActiveSession[2]` | 64 Б | 64 Б |
| всего | | **524 Б** | **524 Б** (область 768 Б, запас 244 Б) |

Адрес области: `MARLIN_EEPROM_SIZE - FB_G6_PRINT_JOURNAL_REGION`, на целевой
плате `4096 - 768 = 3328` (`0xD00`). Проверка непересечения с настройками —
`static_assert` в `module/settings.cpp`.

Дополнительно в `noinit`-RAM (не в EEPROM) лежит запись аварии
`EmergencyRecord` (16 Б: `magic` `0x31455246` (`"FRE1"`), `cause`, `source`,
`crc8`, резерв) — она переживает программный сброс (`hal.reboot()`, кнопка KILL)
и разбирается в `init()`; снятие питания её теряет, что фиксируется битом
`FLAG_EMERGENCY_DETAIL_LOST`. Размещение — `__attribute__((section(".noinit")))`;
факт сохранения обязан быть подтверждён сборкой и на принтере (R3).

## 3. Производные значения (не хранятся)

| Значение | Источник | Где используется |
| --- | --- | --- |
| Локализованное имя причины | `switch (cause)` → `GET_TEXT_F(MSG_STOP_CAUSE_*)` | модальное окно, журнал |
| Локализованное имя источника | `switch (source)` → `GET_TEXT_F(MSG_STOP_SOURCE_*)` | модальное окно, журнал |
| Длительность `ЧЧ:ММ:СС` | `duration_t(duration_s).toString(buf)` | модальное окно, журнал |
| Порядковый номер `#NN` | `1 + (count - 1 - index_from_newest)` | журнал |
| «Оценка» рядом с длительностью | `flags & FLAG_ESTIMATED_DURATION` | модальное окно (`~`), журнал |

## 4. Правила валидации (при чтении и при записи)

| # | Правило | Реакция на нарушение |
| --- | --- | --- |
| V1 | `magic` и `version` заголовка совпадают | журнал пуст, ошибка не поднимается, настройки не сбрасываются |
| V2 | `slots == FB_G6_PRINT_JOURNAL_SLOTS` | журнал пуст (смена глубины = новая раскладка) |
| V3 | `head < slots`, `count <= slots` | заголовок пересобирается сканированием (R2) |
| V4 | `crc8` слота | слот пропускается, остальные читаются |
| V5 | `crc8` активной сессии | слот игнорируется, берётся второй; если оба битые — «активной сессии нет» |
| V6 | `file[12] == '\0'` после чтения | принудительная терминация |
| V7 | `percent <= 100` или `0xFF` | иначе `0xFF` (неизвестно) |
| V8 | `duration_s <= 999999` | иначе `999999` (клампится при записи) |
| V9 | `cause`/`source`/`stage` — известные значения | иначе `CAUSE_UNKNOWN`/`SOURCE_UNKNOWN`/`STAGE_NONE` при отображении |
| V10 | область журнала не пересекает `SettingsData` | ошибка компиляции (`static_assert`), не рантайм |

## 5. Состояния сессии и переходы

```text
                 start_session()                 pause
   [IDLE] ───────────────────────▶ [PRINTING] ─────────▶ [PAUSED]
     ▲                                │  ▲                  │
     │ end_session(COMPLETED/ABORT/…) │  └──── resume ──────┘
     │                                │
     │                                ├── filament change ──▶ [FILAMENT_CHANGE]
     │                                │
     │                                ├── file EOF ────────▶ [FINISHING]
     │                                │                        │
     │◀─────────── end_session(COMPLETED) ◀──── M1001 ─────────┘
     │
     │◀─────────── end_session(ABORT_*/MEDIA_ERROR, source) ───┐
     │                                                         │
     └──────────── reboot с active=1 ──▶ [RESET EVENT] ────────┘
```

Правила переходов:
1. `start_session()` вызывается из `startOrResumeJob()` (`MarlinCore.cpp:347-357`)
   — единая воронка для M24, экрана, WiFi и автозапуска. Повторный вызов при
   уже активной сессии — только обновление контрольной записи (не новое событие).
2. `end_session()` **идемпотентен**: если активной сессии нет, событие не
   создаётся (защита от задвоения при двойном вызове abort/finish).
3. `end_session()` всегда сначала пишет `StopEvent`, затем закрывает
   `ActiveSession`; обратный порядок допускает потерю причины при сбросе между
   двумя записями. Чтобы сброс в этом окне не создал дубль, при загрузке
   проверяется последнее терминальное событие (см. §2.3) и синтез сброса
   пропускается.
4. Сброс без активной сессии события не создаёт (edge case «сброс сразу после
   штатного завершения»).
5. `kill()`/`loud_kill()` работают в нормальном контексте: выставляются
   `FLAG_EMERGENCY`, `emergency_cause`, `emergency_source` в RAM и
   `noinit`-запись `EmergencyRecord`, затем выполняется best-effort
   `append(StopEvent)` в EEPROM. При следующей загрузке `init()` превращает
   валидную запись в `StopEvent(CAUSE_EMERGENCY_*, source,
   FLAG_ESTIMATED_DURATION)`, только если события ещё нет в журнале, и очищает
   её. Если запись невалидна или потеряна (снятие питания) — синтезируется
   событие сброса (`CAUSE_RESET_POWER`) с `FLAG_EMERGENCY_DETAIL_LOST`; при
   неудачной записи события — `FLAG_UNRECORDED_EMERGENCY`.

## 6. Износ и ротация

- Слот переиспользуется каждые 16 событий останова; в типичном сценарии
  (несколько печатей в день) — единицы записей в сутки на слот.
- За событие меняется ≈ 40 байт (28 Б слот + 12 Б заголовок), остальные байты
  не пишутся благодаря сравнению в `PersistentStore::write_data`.
- При ресурсе 100 000 циклов на байт (консервативная оценка Marlin) запас —
  ≳1,5 млн остановок на слот.
- Контрольная запись активной сессии меняет ≈ 6–8 байт (seq, elapsed, percent,
  crc) раз в 300 с при печати: ~1,9 тыс. записей за 160 ч печати.

## 7. Границы и допущения

- Глубина журнала — 16 событий (FR-008, `Assumptions` спеки); при переполнении
  вытесняется самое старое, новые не теряются.
- Имя файла хранится в DOS 8.3 (13 байт) — длинное имя (`card.longFilename`)
  не сохраняется ради бюджета EEPROM; на экране события показывается 8.3-имя.
  Для текущего экрана завершения по-прежнему используется длинное имя.
- Время — только длительность печати (секунды от старта задания), без
  календарной даты: RTC на плате нет (уточнение из `spec.md`, Clarifications).
- `percent` при сбросе — из последней контрольной записи (может отставать до
  `FB_G6_PRINT_JOURNAL_CHECKPOINT_S` секунд).
