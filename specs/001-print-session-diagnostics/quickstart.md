# Quickstart: проверка диагностики сессии печати

**Feature**: `001-print-session-diagnostics` | **Date**: 2026-11-02

Пошаговая проверка, доказывающая, что фича работает end-to-end. Детали формата
и экранов — в [contracts/](./contracts/): `journal-storage.md`,
`stop-reasons.md`, `ui-contract.md`. Требования — в [spec.md](./spec.md).

## 0. Предусловия

- Плата MKS Robin Nano V3, экран MKS TS35 V2.0, MKS WiFi подключён и сопряжён.
- Установлен PlatformIO, доступен `pio`; репозиторий на ветке
  `001-print-session-diagnostics`.
- На SD-карте — файл для печати (например `BENCHY.GCO`), на карте есть запас
  свободного места (для обычной печати, журнал на карту не пишется).
- Зафиксирован базовый размер прошивки до изменений (для SC-006):

```bash
pio run -e mks_robin_nano_v3 -t clean
pio run -e mks_robin_nano_v3 | tee /tmp/fb-g6-base-build.log
```

## 1. Сборка целевого варианта (обязательно, принцип IV)

```bash
pio run -e mks_robin_nano_v3
```

Ожидается:
- сборка без ошибок и новых warning'ов;
- `RAM`/`Flash` из лога — прирост относительно базового не более 2 %
  (SC-006), RAM — не более ~1 КБ;
- артефакт `.pio/build/mks_robin_nano_v3/firmware.bin` обновился.

## 2. Сборка остальных вариантов (принцип IV)

```bash
cp Marlin/build_params.variants/params_104gt.h  Marlin/build_params.h && pio run -e mks_robin_nano_v3
cp Marlin/build_params.variants/params_3950.h   Marlin/build_params.h && pio run -e mks_robin_nano_v3
cp Marlin/build_params.variants/params_bltouch104gt.h Marlin/build_params.h && pio run -e mks_robin_nano_v3
cp Marlin/build_params.variants/params_bltouch3950.h  Marlin/build_params.h && pio run -e mks_robin_nano_v3
git checkout -- Marlin/build_params.h   # вернуть локальный переключатель
```

Ожидается: все четыре сборки успешны, коды причин/журнал не зависят от
термистора и BLTouch (фича не трогает probing/homing).

## 3. Форматирование

```bash
buildroot/bin/format_code feature/print_session.cpp feature/print_session.h
# и остальные изменённые файлы по списку из plan.md
git diff --stat   # форматирование не должно затрагивать посторонние файлы
```

## 4. Функциональные сценарии на принтере

Перед сценариями: прошить `firmware.bin` с SD-карты, дождаться загрузки.
`Initialize EEPROM` **не требуется** (FR-012) — если после прошивки настройки
сброшены, это регрессия.

Для каждого сценария фиксируйте: что показало модальное окно, что появилось в
журнале, что произошло с нагревом/осями/экраном.

### S1. Отмена с экрана (US1, FR-004, FR-015)

1. Запустить печать `BENCHY.GCO`, дождаться 10–15 %.
2. Нажать «Стоп» на TFT-экране печати.

Ожидается:
- модальное окно: причина «Отменено», источник «Экран», длительность и
  процент на момент отмены;
- нагрев выключен, X/Y уехали в домашнюю позицию (`G28XY`), **Z не изменился**;
- журнал: новое событие сверху с тем же содержимым;
- касание в любом месте закрывает окно и возвращает на экран, который был до
  останова.

### S2. Отмена по сети (US1 сценарий 1, US3 сценарий 1)

1. Запустить печать, дождаться 10–15 %.
2. Отправить остановку печати из WiFi-приложения (M26 через MKS WiFi).

Ожидается: модальное окно «Отменено · Сеть» (источник отличается от S1),
поведение осей/нагрева как в S1, запись в журнале с источником «Сеть».

### S3. Отмена из консоли (FR-004)

1. Запустить печать.
2. Подключиться по USB и отправить `M524`.

Ожидается: модальное окно «Отменено · Консоль», запись в журнале с источником
«Консоль».

### S4. Извлечение карты во время печати (US1 сценарий 5, FR-004)

1. Запустить печать, дождаться 10–15 %.
2. Извлечь SD-карту.

Ожидается:
- печать прекращается, модальное окно «Ошибка носителя · SD-карта»;
- нагрев выключен, X/Y паркуются, Z не меняется;
- запись в журнале сохранилась (журнал в EEPROM, карта уже недоступна);
- ранее записанные события журнала не потеряны.

### S5. Сброс по питанию во время печати (US1 сценарий 2, FR-001)

1. Запустить печать, дождаться 10–15 %.
2. Выключить питание принтера, подождать 5 с, включить.

Ожидается:
- после загрузки в журнале — событие «Сброс: питание» с **оценочной**
  длительностью (`~`) и процентом из последней контрольной записи;
- модальное окно при загрузке не показывается (причина доступна в журнале);
- штатное завершение не фиксируется (события «Завершено» нет).

### S6. Программный/кнопочный сброс во время печати (FR-001)

1. Запустить печать, нажать кнопку RESET на плате.

Ожидается: в журнале — «Сброс: программа/кнопка» (отличается от S5).

### S7. Штатное завершение (US1 сценарий 3, FR-005)

1. Напечатать короткий файл до конца.

Ожидается:
- экран «Printing Finished» работает как раньше, модальное окно причины не
  появляется;
- в журнале — «Завершено · Прошивка» с полной длительностью и 100 %;
- после завершения приводы обесточиваются (`M84`, `SD_FINISHED_RELEASECOMMAND`).

### S8. Сброс сразу после завершения (edge case)

1. Дождаться конца печати (S7), сразу выключить и включить питание.

Ожидается: события «Сброс» **нет** (задвоения нет), в журнале остаётся только
«Завершено».

### S9. Переполнение журнала (US1 сценарий 4, FR-008)

1. Выполнить 17 коротких остановок (запуск → отмена через 5–10 с).
2. Открыть журнал.

Ожидается: в журнале ровно 16 событий, самое старое вытеснено, самое новое
присутствует; порядок — новые сверху; прокрутка работает.

### S10. Аварийная остановка (FR-005, FR-007, FR-013)

Необязательный сценарий (требует перезагрузки принтера):

1. Во время печати отправить `M112` из консоли.
2. Дождаться аварийного экрана и выполнить сброс кнопкой RESET (или `M999`,
   если прошивка его обрабатывает).

Ожидается:
- аварийный экран (`KILLED`) показывается, модальное окно причины его **не**
  перекрывает;
- в журнале **после программного сброса** — «Авария: M112» с источником
  «Консоль» (событие пишется best-effort сразу в `kill()`, иначе — из
  `noinit`-записи при загрузке);
- после перезагрузки принтер работает штатно, защиты не отключены.

> При снятии питания вместо `M999` деталь аварии может быть потеряна:
> ожидается `Сброс: питание` + пометка `FLAG_EMERGENCY_DETAIL_LOST`.

> Термозащиту искусственно не провоцировать: достаточно подтвердить, что
> `loud_kill()` не изменён, а причина `EMERGENCY_THERMAL` присутствует в
> таблице кодов.

### S11. Энергонезависимость журнала (SC-003)

1. Выполнить 3–5 остановок.
2. Пять раз выключить/включить питание.

Ожидается: во всех пяти циклах журнал читается полностью, записи не теряются и
не портятся.

### S12. Настройки не пострадали (FR-012)

1. До прошивки сохранить вывод `M503` (USB-консоль).
2. После прошивки и первого запуска повторить `M503`.

Ожидается: состав и значения настроек совпадают (кроме ожидаемого сброса из-за
`EEPROM_INIT_NOW`/`build_hash`, если он был и до фичи); `Initialize EEPROM`
не требуется; журнал при этом не стирается.

### S13. Отсутствие влияния на печать (SC-005)

1. Напечатать модель с тонкими стенками/дугами (проверка на рывки).
2. В процессе наблюдать поверхность и счётчик времени; сравнить с печатью до
   фичи.

Ожидается: нет пауз движения, сравнимых с записью EEPROM (≤ 300 мс на событие
и ≤ 60 мс на контрольную запись раз в 5 минут); качество не изменилось;
время печати того же G-code отличается от печати без фичи не более чем на 1 %.

### S14. Пустой/битый журнал (edge cases)

1. Сразу после `M502`+`M500` (или первой прошивки) открыть журнал.

Ожидается: «Журнал пуст», без ошибок и без сброса настроек; после первой
остановки журнал заполняется.

### S15. Длительные прогоны и серия остановок (SC-002, SC-004)

1. Три печати подряд длительностью ≥ 4 ч; в каждой — 2–3 остановки (S1/S4).
2. Выполнить 10 остановок подряд разными способами (S1–S4).

Ожидается: журнал после каждого прогона цел (нет «пустого»/битого журнала),
все 10 остановок присутствуют в журнале, ни одной «немой».

### S16. Внутренняя остановка `stop()` (FR-001, код `0x50`)

Необязательный сценарий (требует воспроизведения сбоя probe/`stop()`):

1. Вызвать внутреннюю остановку `stop()` (например, ошибка probing).
2. Открыть журнал.

Ожидается: запись «Остановлено прошивкой · Прошивка»; поведение осей/нагрева
как в `contracts/stop-reasons.md` §3, строка `INTERNAL_STOP`.

## 5. Критерии приёмки (из spec.md)

| ID | Как проверить |
| --- | --- |
| SC-001 | S1–S4: у каждой остановки корректные причина и источник (≥ 3 сценария) |
| SC-002 | S15: три длительных прогона ≥ 4 ч с периодическими остановками — журнал цел |
| SC-003 | S11 (5 циклов питания) |
| SC-004 | S15: серия из ≥ 10 остановок — ни одной «немой» (каждая есть в журнале) |
| SC-005 | S13 |
| SC-006 | сравнение размера из шага 1 |
| SC-007 | с главного экрана: касание иконки «Настройки» → первый пункт «Журнал остановок» → причина последней остановки видна; итого 2 действия, прокрутки нет |

## 6. Что приложить к PR

- лог сборки с `RAM`/`Flash` до и после (SC-006);
- результат четырёх сборок из шага 2;
- список пройденных сценариев S1–S16 с фактическим поведением;
- какой `Marlin/build_params.h` использовался при прошивке;
- нужна ли переинициализация EEPROM (ожидается: нет);
- явно отметить непроверенное на железе (например, S10 при отказе от проверки).
