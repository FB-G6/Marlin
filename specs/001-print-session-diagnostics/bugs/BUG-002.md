# Bug Report: Остановка по M524 из консоли записывается как «Причина неизвестна»

**Type**: Untested flow
**Severity**: High
**Feature**: `001-print-session-diagnostics`
**Reported**: 2026-11-04
**Status**: Patched
**Patched**: 2026-11-04
**Verified**: 2026-11-04 — проверено на принтере: журнал «Отменено | Консоль», окно причины появляется, экранный путь не изменился
**Build**: `FBG6-2.1.2.8-104gt` (Nov 4 2026 13:47, исправлен BUG-001)
**Hardware**: MKS Robin Nano V3 + MKS TS35 V2.0

## Description

Остановка печати командой `M524` по USB-консоли не атрибутируется источнику
«Консоль». Печать отменяется штатно (движение стоит, нагреватели выключены,
перезагрузки нет), но:

- в журнале остановок событие записывается как **«Причина неизвестна»**
  (код `0x7F`) с источником `SOURCE_UNKNOWN`;
- модальное окно причины **не показывается** (для `CAUSE_UNKNOWN`
  `modal_pending` не выставляется — так задумано в `end_session()`);
- в контракте `contracts/stop-reasons.md` §1 для `0x12` `CAUSE_ABORT_HOST`
  явно указан «`M524.cpp`, emergency-парсер M524» с источником
  `SOURCE_HOST`, то есть ожидаемое поведение зафиксировано и не выполняется.

Это ломает US3 (различение внешних и внутренних остановок) и SC-001
(«100 % искусственно вызванных остановок дают корректную причину и источник,
не менее 3 разных сценариев»): канал «консоль» из трёх сценариев даёт
неопределённую причину.

### Условия воспроизведения

1. Прошивка с `FB_G6_PRINT_JOURNAL` (`FB_G6_PRINT_JOURNAL_MODAL` включён).
2. Запуск печати с SD (`M23 <файл>` + `M24`) либо с экрана.
3. `M524` по USB-консоли (в любой момент — во время нагрева или печати).
4. Окно причины не появляется; в журнале новая запись — «Причина неизвестна».

Проверено на принтере 2026-11-04: запись `#8 Причина неизвестна`,
окно не появилось; `M27` → `Not SD printing`, нагреватели выключены,
сброса нет.

## Root Cause Analysis

Цепочка обработки `M524`, отправленного хостом:

1. `feature/e_parser.h:219` — аварийный парсер (работает в контексте приёма
   символов, до очереди команд) выставляет `sd_abort_by_M524 = true`.
2. `module/temperature.cpp` (блок `if (emergency_parser.sd_abort_by_M524)`):
   ```cpp
   card.flag.abort_sd_printing = true;          // ← флаг ставится ДО команды
   gcode.process_subcommands_now(F("M524"));
   ```
3. `sd/cardreader.h:368`:
   ```cpp
   #define IS_SD_PRINTING()  (card.flag.sdprinting && !card.flag.abort_sd_printing)
   ```
   После шага 2 `IS_SD_PRINTING()` уже **false**.
4. В `gcode/sd/M524.cpp` проверка `if (IS_SD_PRINTING())` не проходит →
   ветка `else if (card.isMounted()) card.closefile();` — `note_source()`
   не вызывается.
5. Главный цикл (`MarlinCore.cpp`, `if (card.flag.abort_sd_printing)
   abortSDPrinting();`) выполняет `take_source()` → `SOURCE_UNKNOWN` →
   `end_session(CAUSE_UNKNOWN, SOURCE_UNKNOWN)` → запись «Причина неизвестна»,
   `modal_pending` не выставляется.

Почему не поймали раньше:

- ручные проверки S2/S3 (`quickstart.md`), где вызывается `M524`, не
  выполнялись (T039/T045 открыты);
- в тестах BUG-001 остановка из консоли шла через `M108` + `M524` и
  выглядела как «просто ещё один сбой без окна» — сам факт отсутствия окна
  тогда списали на старую сборку;
- аварийный парсер — отдельный путь, который не виден из `M524.cpp`;
  в плане (Фаза B, п. 11) он упомянут как источник метки, но условие
  `IS_SD_PRINTING()` в нём не проверялось.

Побочное наблюдение: `note_source()` сейчас «последний побеждает». Если
аборт уже запрошен по другой причине (например, извлечение карты), `M524`
в этом окне перезапишет источник на «Консоль». Окно между постановкой флага
и обработкой в главном цикле — единицы миллисекунд, поэтому отдельно не
исправляется; зафиксировано как ограничение.

## Recommended Fix

1. **Код** (`Marlin/src/gcode/sd/M524.cpp`): различать «печать идёт» и
   «аборт уже запрошен аварийным парсером»:

   ```cpp
   const bool pending_abort = card.flag.abort_sd_printing;
   if (IS_SD_PRINTING() || pending_abort) {
     TERN_(FB_G6_PRINT_JOURNAL, print_session.note_source(SOURCE_HOST));
     if (!pending_abort) card.abortFilePrintSoon();
   }
   else if (card.isMounted())
     card.closefile();
   ```

   Повторный `abortFilePrintSoon()` при уже установленном флаге не нужен и
   опасен: он присваивает `abort_sd_printing = isFileOpen()`, то есть при
   закрытом файле мог бы снять уже запрошенный аборт.

2. `/speckit.bugfix.patch` — обновить артефакты:
   - `spec.md`: уточнение к FR-004 (остановка по `M524` из консоли имеет
     источник «Консоль» и причину «Отменено») и SC-001;
   - `plan.md`: в Фазе B п. 11 зафиксировать условие аварийного парсера
     (`abort_sd_printing` выставляется до вызова `M524`, `IS_SD_PRINTING()`
     уже false); риск R9;
   - `contracts/stop-reasons.md`: пометить в §1, что путь «emergency-парсер
     M524» требует отдельной проверки `abort_sd_printing`;
   - `tasks.md`: переоткрыть T024, добавить T057 (исправление) и T058
     (проверка на принтере).

3. `/speckit.bugfix.verify` — проверить согласованность артефактов.
4. `/speckit.implement` — пересобрать `mks_robin_nano_v3`, прошить, проверить
   `M524` из консоли (окно + журнал), контроль — остановка с экрана.
