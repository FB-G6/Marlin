# Bug Report: Остановка по M524 из консоли не прерывает ожидание нагрева

**Type**: Untested flow
**Severity**: Medium
**Feature**: `001-print-session-diagnostics`
**Reported**: 2026-11-04
**Status**: Patched
**Patched**: 2026-11-04
**Verified**: 2026-11-04 — проверено на принтере: `M524` при 136 °C (цель 170) останавливает печать за ~4 с, нагреватели выключены, окно «Отменено / Консоль», перезагрузки нет
**Build**: `FBG6-2.1.2.8-104gt`, sha256 `fb50bf13500c808e60ab2f1ee57d6dab2ac64dae7c8a3b31fda77d8c8f97d065` (исправлены BUG-001, BUG-002)
**Hardware**: MKS Robin Nano V3 + MKS TS35 V2.0

## Description

Если `M524` приходит из консоли, пока принтер находится в блокирующем
ожидании (`M109`/`M190` — нагрев, `M0`/`M1` — подтверждение), печать
**не останавливается сразу**: аборт запрашивается, но его обработка
выполняется только в главном цикле, а главный цикл в это время не
крутится. В результате:

- нагреватели продолжают греть до целевой температуры;
- печать и журнал не меняются — записи об остановке нет, окно причины
  не показывается;
- фактическая остановка происходит только после выхода из ожидания
  (или после `M108`), иногда через минуты после команды.

Наблюдение на принтере 2026-11-04: `M524` отправлен во время ожидания
нагрева — в течение следующих 20 с принтер продолжал греть, реакции не было;
после `M108` печать отменилась за ~3 с (журнал «Отменено | Консоль»).

После исправления (2026-11-04, `sha256 fb50bf13…`): `M524` при `T:136.56
/170.00`, команда выполнена на 7.1 с, `M27` → `Not SD printing` на 18.3 с,
`M105` → `T:154.63 /0.00 B:52.94 /0.00 @:0 B@:0` (нагреватели off), окно
причины «Отменено / Консоль», перезагрузки нет.

Экранный путь ведёт себя иначе и правильно: `MarlinUI::abort_print()`
(`lcd/marlinui.cpp`) перед `card.abortFilePrintSoon()` сбрасывает
`wait_for_heatup` и `wait_for_user`, поэтому ожидание обрывается сразу.
`M524` этого не делает — остановка по внешней команде оказывается
«слабее» остановки с экрана.

Затрагивает US3 (внешние остановки) и SC-001: сценарий «остановка по
консоли» не даёт своевременной остановки, а FR-015 (нагреватели
выключаются при отмене) выполняется с задержкой на всё время ожидания.

### Условия воспроизведения

1. Прошивка с `FB_G6_PRINT_JOURNAL`, печать с SD (`M23 …` + `M24`).
2. В файле `M109 S170` (ожидание нагрева) — либо `M0` в начале печати.
3. `M524` по USB-консоли во время ожидания.
4. Принтер продолжает греть; остановка — только по окончании ожидания
   или после `M108`.

## Root Cause Analysis

1. `M524` из консоли разбирается аварийным парсером (`feature/e_parser.h`,
   `EP_M524`) и ставит `sd_abort_by_M524`.
2. `Temperature::task()` (вызывается из `idle()`, в том числе из цикла
   `wait_for_hotend`) выставляет `card.flag.abort_sd_printing = true` и
   сразу выполняет `M524` — источник фиксируется (после BUG-002).
3. Сам аборт выполняет **только** главный цикл:
   ```cpp
   void loop() {
     do {
       idle();
       if (card.flag.abort_sd_printing) abortSDPrinting();  // ← здесь
       queue.advance();
       …
   ```
4. Пока выполняется `M109`/`M190`/`M0`, вызывается только `idle()`;
   `loop()` не выполняется, поэтому аборт висит во флаге, а нагреватели
   продолжают работать.
5. `M108` работает потому, что аварийный парсер сбрасывает
   `wait_for_heatup` прямо в прерывании — ожидание обрывается, управление
   возвращается в `loop()`, флаг обрабатывается.

Почему не поймали раньше: проверки остановки из консоли шли во время
печати (или после нагрева) и завершались `M108`, поэтому задержка
списывалась на «аборт обрабатывается в главном цикле».

## Recommended Fix

`Marlin/src/gcode/sd/M524.cpp`, ветка остановки печати:

```cpp
if (IS_SD_PRINTING() || pending_abort) {
  // A stop must break a blocking heating or confirmation wait, like the
  // UI stop does; otherwise the print keeps heating until the wait ends.
  wait_for_heatup = false;
  TERN_(HAS_RESUME_CONTINUE, wait_for_user = false);
  TERN_(FB_G6_PRINT_JOURNAL, print_session.note_source(SOURCE_HOST));
  if (!pending_abort) card.abortFilePrintSoon();
}
```

Сброс выполняется только в ветке «печать действительно останавливается»:
`M524` при простое (ветка `closefile()`) не должен срывать чужой `M109`.

Проверки:

- сборка `pio run -e mks_robin_nano_v3` без новых предупреждений;
- на принтере: `M524` во время `M109` → остановка за секунды, нагреватели
  выключены, окно «Отменено / Консоль»; остановка с экрана и `M108` —
  без изменений.

## Заметки о влиянии

- EEPROM-раскладка и настройки не затрагиваются.
- Защиты (thermal protection, watchdog, `SanityCheck`) не ослабляются:
  меняется только момент выхода из блокирующего ожидания.
- Поведение `M108` не меняется.
