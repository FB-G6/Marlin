# Contract: экранный интерфейс причины и журнала

**Feature**: `001-print-session-diagnostics` | **Версия контракта**: 1

UI-контракт для `TFT_COLOR_UI` (MKS TS35 V2.0, 320×480, вертикально).
Реализация — `Marlin/src/lcd/tft/ui_320x480.cpp` (модальный экран) и
`Marlin/src/lcd/menu/menu_journal.cpp` (журнал).

## 1. Модальное окно причины (FR-002)

### 1.1 Когда показывается

| Событие | Показывать | Комментарий |
| --- | --- | --- |
| `ABORT_*`, `MEDIA_ERROR`, `INTERNAL_STOP` | да, сразу после останова | пользователь присутствует, причина важна |
| `COMPLETED` | нет | уже есть экран «Printing Finished» (`ui.screen_num = 3`) |
| `EMERGENCY_*` | нет | приоритет у аварийного экрана `kill_screen()` (FR-002) |
| `RESET_*` (синтезировано при загрузке) | нет | причина доступна в журнале (US1 сценарий 2) |
| `marlin_state == MF_KILLED` | нет | аварийный экран не перекрывается |
| `wait_for_user == true` | отложить | активный диалог паузы/подтверждения не перекрывается |
| `FB_G6_PRINT_JOURNAL_MODAL` выключен | нет | остаётся только журнал |

Показ выполняется из `print_session.task()` (вызывается из `idle()`), а не из
обработчика останова: к этому моменту очередь команд очищена, движение
остановлено, экран не перерисовывается в критическом участке.

### 1.2 Как показывается

```cpp
ui.push_current_screen();                       // запомнить текущий экран
ui.goto_screen(MarlinUI::stop_reason_screen);   // новый экран, очищает LCD
```

- `push_current_screen()` обязателен, но фактическая цель возврата — статус-экран:
  `ui.abort_print()` вызывает `return_to_status()` до показа окна из `idle()`
  (`lcd/marlinui.cpp:1656-1668`). Закрытие возвращает на статус-экран; возврат
  ровно на экран до останова потребовал бы отдельного сохранения стека TFT.
- В `TFT_COLOR_UI` нет композитинга и альфа-канала
  (`lcd/tft/canvas.cpp:52-64`), поэтому «модальность» реализуется отдельным
  непрозрачным экраном поверх стека, а не полупрозрачным оверлеем. Это
  осознанное уточнение формулировки спеки (research R9).
- Нельзя реализовать окно контролом `CLICK` на статус-экране:
  `status_screen()` перехватывает клик и уводит в `menu_main`
  (`lcd/marlinui.cpp:667-675`).

### 1.3 Содержимое (320×480)

```text
┌──────────────────────────────────────┐
│  Остановка печати            (заголовок, MSG_STOP_REASON_TITLE)
│  ────────────────────────────────
│  Причина:  Отменено                  (MSG_STOP_CAUSE_*)
│  Источник: Экран                     (MSG_STOP_SOURCE_*)
│  Время:    01:23:45                  (duration_t, "~" если оценочное)
│  Файл:     BENCHY.GCO                (8.3)
│  Прогресс: 42%                       (или "—" при 0xFF)
│  ────────────────────────────────
│  Коснитесь экрана, чтобы закрыть     (MSG_STOP_TAP_TO_CLOSE)
└──────────────────────────────────────┘
```

- Рисуется `tft.canvas(...)` + `tft.set_background(COLOR_BACKGROUND)` +
  `tft.add_rectangle(...)` (рамка) + `tft.add_text(...)`; шрифт — штатный
  `Helvetica18` (кириллица поддерживается, `DISPLAY_CHARSET_RUS`).
- Все строки — через `GET_TEXT_F(MSG_*)`; причина и источник выбираются
  функцией `switch`, возвращающей `FSTR_P`, чтобы смена языка применялась
  сразу (research R11).
- Длинное имя файла не используется: в журнале хранится DOS 8.3 (13 байт).

### 1.4 Закрытие

- `touch.clear(); touch.add_control(BACK, 0, 0, TFT_WIDTH, TFT_HEIGHT);` —
  касание в любом месте → `ui.goto_previous_screen()` (штатный обработчик
  `BACK`, `lcd/tft/touch.cpp:179`).
- Окно не имеет таймаута: висит до касания (пользователь мог отойти).
- Повторная остановка до закрытия окна: новое событие заменяет содержимое
  (экран перерисовывается с последним событием), стек не растёт — повторный
  `push_current_screen()` не выполняется, если текущий экран уже
  `stop_reason_screen`.

## 2. Журнал остановок (FR-014, FR-016, SC-007)

### 2.1 Точка входа

`Статус-экран → иконка «Настройки» (menu_configuration) → «Журнал остановок»`
— 2 касания с главного экрана (SC-007). Пункт
`SUBMENU(MSG_STOP_JOURNAL, menu_journal)` добавляется в
`lcd/menu/menu_configuration.cpp` сразу после `BACK_ITEM` (до
`ADVANCED_SETTINGS`), чтобы на 320×480 он был виден без прокрутки.

### 2.2 Список

```text
┌──────────────────────────────────────┐
│ < Назад                              │
│ #16 Отменено · Экран · 01:23:45      │  ← новое событие сверху
│     BENCHY.GCO · 42%                 │
│ #15 Завершено · Прошивка · 04:10:02  │
│     CUBE.GCO · 100%                  │
│ ...                                  │
└──────────────────────────────────────┘
```

- Порядок: по убыванию `seq` (новые сверху), максимум
  `FB_G6_PRINT_JOURNAL_SLOTS` (16) событий.
- Формат строки 1: `#NN <причина> · <источник> · ЧЧ:ММ:СС` (`~` для оценочной
  длительности).
- Формат строки 2: `<файл 8.3> · <процент>%` (или `—` при неизвестном).

> Уточнение реализации: вместо `·` используется ASCII-разделитель `|`, потому
> что символ `·` (U+00B7) есть только в тестовой строке набора символов и не
> гарантирован в шрифтах `TFT_COLOR_UI`. Это единственное расхождение с
> форматом выше; содержание строк не меняется.
- Реализация: `START_MENU()` + `BACK_ITEM(MSG_MAIN)` + по два
  `STATIC_ITEM_F(...)` на событие; прокрутка и касания — штатные
  (`lcd/menu/menu_item.h`, `lcd/tft/ui_common.cpp:132-183`).
- Пустой журнал: один `STATIC_ITEM(MSG_STOP_JOURNAL_EMPTY)` —
  «Журнал пуст» / "Journal is empty".
- Повреждённые записи не отображаются; если повреждены все — экран пустого
  журнала (без сообщения об ошибке, настройки не сбрасываются).

### 2.3 Ограничения

- Журнал только для чтения: ни один пункт не меняет состояние принтера,
  не двигает оси и не запускает печать.
- Нет вывода журнала в консоль, по сети или на SD (FR-016).
- Экран не блокирует печать: открывается только из меню, когда печать не
  активна (пункт меню доступен и во время печати, но список статичен).

## 4. Совместимость с существующими экранами

- Экран «Printing Finished» (`ui.screen_num = 3`) не меняется; модальное окно
  для `COMPLETED` не показывается, чтобы не дублировать его.
- Аварийный экран (`MarlinUI::kill_screen`, `ui_320x480.cpp:150-173`) имеет
  приоритет; модальное окно причины при `MF_KILLED` не открывается.
- Касания: новый экран регистрирует единственный полноэкранный `BACK`, поэтому
  не конфликтует с контролами предыдущего экрана (они очищаются
  `ui.clear_lcd()` внутри `goto_screen`).
- Навигация меню (`BACK_ITEM`, прокрутка, `PREVOUS_SCREEN`) не меняется.
