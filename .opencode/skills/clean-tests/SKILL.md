# Clean Tests

В этом репозитории нет классических юнит-тестов. «Тест» — это сборка эталонной
конфигурации и/или запуск симулятора. Правила T1-T9 применяются к этому
контексту.

## T1: Проверяй всё, что может сломаться

Недостаточно собрать один env. Если правка затрагивает конфигурацию, проверь
комбинации, которые реально поставляются:

- термистор 104GT **и** 3950;
- с `FB_G6_BLTOUCH` **и** без;
- сборка с кастомными экранами **и** без них, если правка в общем коде LCD.

```bash
for variant in params_104gt params_3950 params_bltouch104gt params_bltouch3950; do
  cp Marlin/build_params.variants/$variant.h Marlin/build_params.h
  pio run -e mks_robin_nano_v3
done
```

Не забывай вернуть исходный `Marlin/build_params.h` после проверки.

## T2: Используй инструменты покрытия как ориентир

Для прошивки «покрытие» — это матрица конфигураций из
`.github/workflows/test-builds.yml` и `buildroot/tests`. Смотри, какие
платформы затронуты правкой, и собирай соответствующие.

## T3: Не пропускай «тривиальные» проверки

Сборка платы, которая не является целевой, всё равно ловит ошибки в общем коде.
Дешёвая проверка лучше, чем никакой.

## T4: Пропущенная проверка — вопрос о неоднозначности

Если тест отключён (`#` в матрице CI, закомментированный env), это должно быть
объяснено. Не оставляй «пока отключим» без причины и ссылки на проблему.

## T5: Проверяй граничные условия

Для прошивки это:

- минимальные/максимальные размеры стола и хода (`X_MIN_POS`, `X_MAX_POS`);
- нулевые и максимальные температуры, `TEMP_SENSOR_0`;
- пустой файл на SD, конец файла, очень длинная строка G-кода;
- переполнение счётчиков (`uint8_t` для индексов > 255);
- деление на ноль в шаговых/скоростных расчётах.

## T6: Исчерпывающе проверяй рядом с багом

Нашёл баг — проверь все похожие места: другие оси, другие экструдеры, другие
HAL, другие варианты конфигурации. Баги в прошивке кластеризуются по осям и
платам.

## T7: Паттерны падений информативны

Если падает несколько конфигураций с одним признаком — проблема не в
конфигурации, а в общем коде или в `Conditionals_*.h`.

## T8: Покрытие подсказывает дизайн

Если код невозможно собрать без десятка флагов, возможно, он слишком связан.
Выноси под `#if ENABLED(...)` только то, что действительно опционально.

## T9: Проверки должны быть быстрыми

Полная матрица CI — минуты. Локальный цикл обратной связи должен быть коротким:

```bash
# быстрый цикл: только целевой env
pio run -e mks_robin_nano_v3

# затем — эталонные конфигурации
make tests-single-local TEST_TARGET=mks_robin_nano_v1v2

# и только потом — всё
make tests-all-local
```

Для логики без железа используй `linux_native` или симулятор:

```bash
pio run -e simulator_macos_release
.pio/build/simulator_macos_release/MarlinSimulator
```

## Организация проверок

### F.I.R.S.T. для прошивки

- **Fast** — сначала один env, потом матрица;
- **Independent** — каждая проверка начинается с чистого конфига
  (`use_example_configs`, `opt_set`, `opt_enable`);
- **Repeatable** — фиксированный `build_params.h` и версия PlatformIO;
- **Self-Validating** — сборка либо проходит, либо нет; «посмотрю глазами» не
  считается;
- **Timely** — проверка добавляется вместе с правкой, а не после релиза.

### Один сценарий на проверку

Не смешивай в одном тесте BLTouch, WiFi и смену термистора: при падении будет
непонятно, что именно сломалось.
