# Правило бойскаута

> «Всегда оставляй лагерь чище, чем он был до тебя.»
> — Роберт Бейден-Пауэлл

> «Всегда выписывай модуль чище, чем брал его.»
> — Роберт Мартин, *Clean Code*

## Философия

Не нужно делать модуль идеальным. Нужно сделать его **немного лучше**, чем он
был. Каждое касание кода — один маленький шаг к лучшему.

## При работе с кодом

Каждый раз, когда трогаешь код, найди **хотя бы одно** небольшое улучшение.

### Быстрые победы

- Переименовать невнятную переменную → `clean-names`
- Удалить комментарий, пересказывающий код → `clean-comments`
- Удалить мёртвый код и неиспользуемые include
- Заменить магическое число именованной константой → `clean-general`
- Вынести глубоко вложенный блок в функцию с понятным именем →
  `clean-functions`

### Более глубокие улучшения

- Разделить функцию, которая делает несколько дел → `clean-functions`
- Убрать дублирование (DRY) → `clean-general`
- Добавить проверку граничного условия
- Улучшить проверяемость/сборку конфигурации → `clean-tests`

## Пример

```cpp
// Задача: исправить баг в этой функции.
void proc(float *out, int n, bool fast) {
  // process data
  for (int i = 0; i < n; i++)
    out[i] = fast ? out[i] * 1.0825f : out[i];
}
```

Не просто исправляй баг. Оставь код чище:

```cpp
constexpr float TAX_RATE = 1.0825f;

// Apply tax to every value in the buffer.
void apply_tax(float *values, const uint8_t count) {
  for (uint8_t i = 0; i < count; i++)
    values[i] *= TAX_RATE;
}
```

**Что изменилось:**
- ✅ понятное имя функции;
- ✅ именованная константа вместо магического числа (G25);
- ✅ фиксированный тип счётчика (CPP4);
- ✅ нет булева флага: вызывающий сам выбирает, применять налог или нет (F3);
- ✅ явный контракт по памяти: массив и его длина.

## Оркестрация скиллов

| Задача | Скилл |
| --- | --- |
| Любой C/C++ в репозитории | `cpp-clean-code` (мастер) |
| Имена переменных, функций, классов | `clean-names` |
| Комментарии и doc-блоки | `clean-comments` |
| Создание и рефакторинг функций | `clean-functions` |
| Качество кода, DRY, магические числа | `clean-general` |
| Тесты и проверочные сборки | `clean-tests` |

## Настрой

**Не надо:**
- оставлять код хуже, чем был;
- говорить «это не мой код»;
- ждать отдельного спринта на рефакторинг;
- делать массовые изменения, не связанные с задачей.

**Надо:**
- делать одно небольшое улучшение с каждым коммитом;
- исправлять то, что видишь, даже если не ты это сломал;
- держать изменения соразмерными задаче;
- оставлять след из улучшений.

## Поведение агента

При работе с кодом:
1. Сначала выполнить запрошенную задачу.
2. Найти хотя бы одну возможность небольшой очистки.
3. Применить подходящий скилл.
4. Отметить улучшение: «Попутно: переименовал `x` в `results` (N1)».

При ревью:
1. Загрузить `cpp-clean-code` для полной проверки.
2. Указывать нарушения по номеру правила.
3. Предлагать инкрементальные улучшения, а не полную переписку.

## Обещание бойскаута

Каждый кусок кода, которого ты коснулся, становится немного лучше.
Не идеальным — лучше. Со временем «лучше» превращается в «отлично».
